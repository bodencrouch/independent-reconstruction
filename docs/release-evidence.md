# Describe the result accurately

Publish only concrete, bounded statements: the reference version and environment,
the candidate snapshot, measured cases, requirement coverage, known mismatches,
contract review method, context/session attestations, and isolation actually used.

Keep a private provenance package with authority and licenses for observations,
analyst exposure records, firewall decisions, context metadata, adapter origin,
oracle version receipts, candidate/toolchain hashes, incident records and audit
heads. Public report export contains counts and digests, not that private material.
Maintain notices for any redistributed code, data, docs, fixtures or tooling that
actually requires them. Privacy redaction is not a way to remove obligations.

This package provides no automatic jurisdiction-specific determination. In the US,
[17 USC 102(b)](https://www.copyright.gov/title17/92chap1.html#102) distinguishes
ideas and methods from copyrightable expression. That distinction alone does not
establish that a particular implementation is independent or clear other rights.
Do not infer freedom from patents, contracts, trademarks, trade secrets or platform
restrictions from a low code-similarity score.

The original user brief inspired this package's requirements. Package authors saw
that conceptual material and host documentation; they did not recreate a reference
implementation from unseen inputs. The package's future implementers use the stricter
handoff process. Preserve this difference in any authorship account.

Use `export` for the measured report. It does not distribute candidate code, select
a new license, publish a repository or create a PR. Actual publication and notice
review are explicit release operations with the user's existing approval constraints.
