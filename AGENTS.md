# Independent Reconstruction

This package builds original implementations from reviewed behavioral contracts.
Use the canonical workflow in docs/architecture.md. Resolve installed skill
symlinks before locating package scripts. This file applies throughout the package.

## Preserve the boundary

- Observer and specification writer may use authorized reference evidence.
- Firewall reviewer checks every requirement and its private provenance.
- Implementer receives only a sealed handoff in a genuinely fresh context.
- Conformance reviewer operates reference and candidate adapters independently.
- Coordinator carries opaque requirement IDs between roles; amendments require review.
- Shared filesystems, role names, prompts and environment variables do not establish isolation.
- Use an OS sandbox or separate VM for enforceable file/network separation.
- Preserve required notices; record source exposure and unknown model training history.
- Never claim the authors of this package did not see the conceptual user brief.

## Implement and report

- Split runtime behavior across ir/ modules; scripts/ are entry points and installers.
- Keep schemas, examples, skills, commands and runtime flags consistent.
- Never copy reference source, plans, tests, comments, distinctive naming or algorithms
  into the implementer's handoff. Observable interface names need explicit review.
- Record observed, inferred and unknown behavior separately; do not invent evidence.
- Keep private evidence and hook payloads out of public output and version control.
- Do not read raw personal archives for package development.
- Similarity is a triage signal. Conformance is a bounded measurement.
- Legal and licensing status remain undetermined by this tooling.
- Quarantine contamination; preserve work; start a new run and implementation context.
- Hooks are project opt-in. Preserve unrelated configuration and avoid global blocking hooks.
- Public and third-party PR creation requires explicit approval in this conversation.
- Do not create filesystem test suites during implementation. Use focused inline
  receipts after all package components are implemented, as required by creation skills.
